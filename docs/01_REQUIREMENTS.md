# 01 — 需求规格

## 项目名称

**基于大语言模型的测试管理平台**

---

## 版本规划总览

| 阶段 | 名称 | 状态 |
|------|------|------|
| V1.0 ~ V1.5 | Demo 闭环（用例管理 → LLM生成 → 执行 → 分析 → 报告） | ✅ 已完成 |
| **第一阶段** | **项目管理 + 模块目录树 + 用例按项目/模块分类** | 🔜 即将开始 |
| 后续阶段 | 需求文本管理、功能测试用例、用户登录等 | 📋 规划中 |

> 本文档列出最终目标的功能范围。标注 🔜 的为第一阶段即将实现，标注 📋 的为后续阶段实现。

---

## 第一阶段功能（🔜 即将实现）

### 1. 项目管理

- 支持创建、编辑、删除、查询项目
- 每个项目包含名称、描述、创建时间等基本信息
- 用例归属到具体项目（`project_id` 必填）
- 前端支持项目切换
- 支持创建"默认测试项目"

### 2. 模块目录管理

- 项目下支持多级模块目录树
- 模块包含名称、父模块引用（`parent_id`）、排序序号（`sort_order`）
- 支持模块的增删改查
- 支持同级模块排序（上移/下移/reorder）
- 用例可挂载到具体模块节点（`module_id` 可选）
- 每个项目可有一个"未分类"默认模块
- 仅允许删除空模块（无子模块、无用例），不做级联删除

### 3. 接口测试用例管理（增强）

- 已有能力保留：API 用例的 CRUD
- 用例字段扩展：在现有字段基础上新增 `project_id`（必填）、`module_id`（可选）、`case_type`、`source`、`priority`、`status`、`is_deleted`
- 支持按项目筛选
- 支持按模块筛选/浏览
- 新建/编辑用例时可选择项目和模块

---

## 后续阶段功能（📋 规划中）

### 4. 需求文本管理

- 支持在项目/模块下添加需求描述文本
- 需求文本作为 AI 生成测试用例的上下文输入
- 支持需求的增删改查

### 5. 功能测试用例管理

- 在接口测试用例之外，新增功能测试用例类型
- 功能测试用例包含：用例标题、前置条件、测试步骤、预期结果
- 支持功能测试用例的 CRUD
- 功能测试用例同样按项目/模块分类

### 6. 功能测试用例生成

- 基于需求文本 + 模块上下文，LLM 生成功能测试用例
- 生成结果可直接入库为功能测试用例

### 7. 场景管理（增强）

- 场景归属到具体项目（增加 `project_id`）
- 场景按项目过滤

### 8. 测试报告（增强）

- 报告归属到具体项目（增加 `project_id`）
- 报告按项目过滤
- 支持针对特定项目生成报告

### 9. 用户登录

- 用户注册与登录
- 基于角色的权限控制
- 数据按用户隔离

## 已有功能（第一阶段保留不变）

以下功能在 V1.5 Demo 中已实现，第一阶段保留不变，不增不减：

| 功能 | 说明 |
|------|------|
| 接口测试用例 CRUD | 名称、方法、URL、请求头、请求体、期望结果 |
| LLM 生成 pytest 测试代码 | DeepSeek 调用，产出可执行 pytest 代码 |
| 规则生成测试代码 | 纯 Python 确定性生成 |
| pytest 执行 | subprocess 执行，日志采集，响应提取 |
| AI 失败分析 | LLM 根因分析，结构化输出 |
| 场景管理 | 场景 CRUD + 有序步骤 + 场景执行 |
| 测试报告 | 一键执行全部场景 + LLM 汇总报告 |
| 参数管理 | parameter.py 在线编辑 |

---

## 非功能需求

- 后端 API 响应时间 < 5s（LLM 调用除外）
- LLM 调用超时时间 60s
- 前端页面首屏加载 < 3s
- SQLite 单文件数据库，无需独立部署（所有阶段保持不变）
- 支持 Windows / macOS 本地开发运行
