## 八、核心概念边界

### AgentSession

- 持续对话容器；
- 绑定 user_id/project_id；
- 可以包含多个 AgentRun；
- 不直接执行 Workflow。

### AgentRun

- 一次具体 Skill 执行；
- 有 workflow_code/version、状态、步骤、预算和结果；
- Runtime 只推进 Run，不把整个 Session 当作一次任务。

### SkillDefinition

首期为代码中的不可变配置，不建数据库表：

- code
- name
- version
- description
- workflow_factory 或 workflow
- required_context
- allowed_tools
- default_max_steps

### ToolDefinition

本任务只建立定义和注册，不执行业务 Tool：

- name
- description
- input_model
- output_model
- read_only
- requires_approval
- idempotent
- required_permission
- handler，可为空或使用 Fake handler 测试

### Artifact

- Runtime 产生的结构化业务结果；
- 本任务只实现通用创建、版本和状态更新；
- 不生成真实测试用例。

### Approval

- 写操作或 GATE 的暂停点；
- Runtime 创建 pending Approval 后，Run 进入 waiting_approval；
- 审批处理 Service 只更新状态并返回结果；继续执行机制留给 T04B/T07。

## 九、Workflow Protocol

不要让一个 `run()` 函数一次执行完整任务且无法恢复。

建议设计为“每次推进一个 Step”：

```python
class AgentWorkflow(Protocol):
    code: str
    version: str

    def initial_state(self, input_data: dict) -> dict:
        ...

    def next_step(self, state: dict) -> str | None:
        ...

    def execute_step(
        self,
        step_name: str,
        state: dict,
        context: RuntimeContext,
    ) -> StepOutcome:
        ...
```

实际命名可以调整，但必须满足：

- 一次只执行一个可持久化步骤；
- StepOutcome 明确新的 state、事件、Artifact、Approval 和终止状态；
- Runtime 可以在任意步骤后停止；
- 不依赖 Python 进程内隐藏状态才能恢复；
- Workflow 不直接 commit 数据库事务；
- Workflow 不直接操作 Agent ORM 对象。

## 十、RuntimeContext 与 StepOutcome

RuntimeContext 最少包含：

- run_id
- session_id
- project_id
- requester_user_id
- db/session factory 或受控 Service 入口
- skill definition
- tool registry
- llm gateway，可空或 Fake
- now provider，测试可注入

StepOutcome 最少表达：

- status：continue/waiting_approval/succeeded/failed
- state_updates 或 next_state
- output_summary
- emitted_events
- artifacts_to_create
- approval_to_create，可空
- error_code/error_message，可空

不得包含模型隐藏思维链。

## 十一、状态转换

集中定义合法状态转换，不允许业务代码任意赋值：

```text
queued → running / cancelled
running → waiting_approval / succeeded / failed / cancelled / interrupted
waiting_approval → running / cancelled / failed
interrupted → queued / failed / cancelled
succeeded / failed / cancelled → 终态，不允许再次推进
```

要求：

- 非法转换抛出明确 Runtime 错误；
- 终态不可再次执行；
- steps_used 不能超过 max_steps；
- 每次执行前检查 cancelled；
- max_steps 超限进入 failed，记录稳定 error_code；
- 不在本任务实现总时间 deadline 新字段。

## 十二、Registry

### SkillRegistry

- register/get/list；
- skill code 唯一；
- 是否允许相同 code 不同 version，由方案明确；
- 未知 Skill 返回明确错误；
- 本任务显式 skill_code 选择，不调用模型路由；
- 只注册内存中的测试 Fake Skill，不添加生产业务 Skill。

### ToolRegistry

- register/get/list；
- tool name 唯一；
- 保存 ToolDefinition；
- 本任务不执行真实 Tool；
- 不允许动态 import 任意路径；
- 不扫描未知来源 SKILL.md。

## 十四、Runtime Runner

本任务实现同步、单步或有界本地循环 Runner，供测试直接调用。

至少支持：

1. 根据显式 skill_code 从 Registry 获取 Skill。
2. 为 queued Run 初始化 state。
3. 执行一个 Workflow Step。
4. 创建 AgentStep。
5. 写 AgentEvent。
6. 更新 input_json/output_json 或 state 保存位置。
7. 创建 Artifact。
8. 创建 Approval 并进入 waiting_approval。
9. 处理 succeeded/failed。
10. 检查 max_steps。

不要实现：

- while True Worker；
- 数据库轮询；
- 多进程锁；
- heartbeat；
- 自动恢复；
- Tool Call 执行；
- 真实 LLM 调用。

## 十五、Fake Workflow 测试场景

测试中定义 Fake Skill，不把 fake 功能写进生产注册表。

至少覆盖：

### 成功流程

```text
queued
→ running
→ step 1 创建 progress event
→ step 2 创建 fake Artifact
→ succeeded
```

### 审批流程

```text
queued
→ running
→ 创建 pending Approval
→ waiting_approval
→ approve/reject Service 状态正确
```

### 失败和预算

- Workflow step 抛出异常 → Run failed + Step failed；
- 未知 Skill；
- 重复注册 Skill/Tool；
- 非法状态转换；
- 终态再次推进；
- max_steps 超限；
- cancelled Run 不执行；
- Message/Event/Step sequence_no 保持唯一和递增；
- Artifact version 递增；
- Approval 不能重复解决；
- 跨项目/用户访问被拒绝。
