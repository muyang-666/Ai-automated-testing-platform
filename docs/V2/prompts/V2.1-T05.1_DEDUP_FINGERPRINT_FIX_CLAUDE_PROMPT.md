## 四、任务目标

建立不会把“同一接口的不同测试场景”误删的确定性指纹，同时支持候选与已有数据库用例使用不同字段形态时正确比较。

### 功能用例指纹

至少使用：

```text
normalized case_name/name
+ canonical steps_json/steps
+ normalized expected_result
+ case_type
```

### API 用例指纹

至少使用：

```text
normalized method
+ canonical URL（含 query 参数规范化）
+ canonical body/request data
+ canonical expected_result
+ case_type
```

同一个 method+url 但 body、expected_result 或 case_type 不同的候选必须保留为不同场景。

## 五、实现规则

1. 支持候选和已有用例的字段别名：
   - function：`case_name` 或 `name`
   - steps：`steps_json` 或 `steps`
   - test data：`test_data_json` 或 `test_data`
   - API body 可能是 dict/list/string/None，也可能是数据库 JSON 字符串
   - expected_result 可能是 dict/string/None
2. JSON 对象 key 顺序不同但内容相同，应生成相同 canonical 表达。
3. URL query 参数顺序不同但语义相同，应尽量归一化为相同结果；无法安全解析时使用稳定 fallback。
4. 不修改原输入对象。
5. 最终 fingerprint 使用 SHA-256 等稳定摘要，不直接返回包含请求体、query token、密码或预期结果的原始拼接字符串。
6. 去重结果中的 fingerprint 只能是安全摘要。
7. 已有用例仍然优先保留，与已有用例重复的候选被标记 duplicate。
8. 候选之间重复时保留第一个。
9. 不使用 embedding、LLM Judge 或不可解释的模糊阈值。
10. 不把 possible similarity 当作 exact duplicate 自动删除。

## 六、已有用例摘要调整

`list_existing_cases` 必须返回足够构造同一指纹的信息。

功能用例摘要至少增加或统一：

- case_name
- steps_json
- expected_result
- case_type

API 用例摘要至少增加：

- method
- url
- body
- expected_result
- case_type

要求：

- 数据库 JSON 字符串安全解析；解析失败使用稳定原字符串 fallback；
- 输出给 Agent 前继续应用现有脱敏规则；
- 不返回 generated_test_code；
- 不返回 Authorization、Cookie、Token、password 等 Secret 明文；
- 如不希望暴露 body/expected，可在查询工具内部生成安全 `dedup_payload` 或 `dedup_fingerprint`，但候选和已有用例必须复用同一算法；
- 方案选择以最小改动、可测试、无 Secret 为准。

## 九、必须新增的回归测试

至少覆盖：

1. 同 method+url，正常 body 与缺密码 body → 不重复。
2. 同 method+url、同 body，不同 expected_result → 不重复。
3. 同 method+url/body/expected，不同 case_type → 不重复。
4. 完全相同 API 场景但 JSON key 顺序不同 → 重复。
5. URL query 参数顺序不同、语义相同 → 重复。
6. API body 是 dict 与等价 JSON string → 重复。
7. 已有 API 用例与候选完全相同 → 候选被标记重复。
8. 同一接口的多个合法不同场景全部进入 keep_indexes。
9. 已有功能用例使用 `name`，候选使用 `case_name`，内容相同 → 重复。
10. 功能用例名称相同但步骤或预期不同 → 不重复。
11. fingerprint 和 DuplicateRelation 输出不包含测试密码、Token、Cookie 等明文。
12. 原 candidates/existing 输入对象调用后保持不变。
13. T05 原有“已有用例优先”行为继续通过。
14. 230 条既有测试全部继续通过。
