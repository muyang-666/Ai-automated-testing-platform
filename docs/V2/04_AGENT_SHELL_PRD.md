# V2 对话 Agent 基础 PRD

> 产品目标：先成为一个可持续交流、按需使用能力的 Agent，再扩展测试业务。
> 当前规划，尚未实现完整产品；测试用例等产物归 V3。

## 1. 用户体验

- 登录后可直接说“你好”“你能做什么”，不要求先选项目或文档。
- “请把刚才那段话概括一下”使用当前历史；普通聊天不会自动创建用例生成任务。
- “使用 notes_summary 整理这段笔记”可加载审核过的通用 Skill。
- “计算这些数字的总和”可调用无副作用计算工具，返回解释；不执行模型生成的 Python 或 eval。
- 能说“不确定，需要你补充一项信息”，而不是猜测业务来源 ID。
- 一轮模型失败后可继续聊天；重试不会重复已经确认的动作。

## 2. 输入和输出

输入支持普通文本、可选显式 Skill、后续消息排队。多模态、上传可执行文件、任意网址工具不在 V2。
回复为自然语言/Markdown，逐步流式展示。系统进度、工具轨迹和错误独立展示，不伪装成模型思考。
不展示隐藏思维链。JSON 是部分内部合同格式，不是所有用户可见回复的格式要求。

## 3. 悬浮工作台

保留最小化/恢复、最大化、拖动、自由缩放和小屏视图。
会话列表可恢复历史；运行中切换展示不能让请求/结果串会话。
运行时显示停止与明确的排队行为；失败/取消后输入框恢复可用。
模型未配置、Worker 未就绪、能力不支持要在开始前解释；不能让用户先点完业务范围才知道无法聊天。
新聊天入口不默认展示需求来源、覆盖矩阵或“用例已保存”；旧业务入口作为兼容能力保留。

## 4. Skill 的产品边界

Skill 是可发现的任务能力说明，不等于代码 Workflow。
V2 只演示 notes_summary 等通用 Skill；加载受控、可解释、可追踪版本。
用户说“生成用例/造数/分析失败”时，尚未接入的能力应明确告知未启用，不假装成功，也不调用旧工作流绕过版本边界。
V3 验收后再将测试 Skill 挂到 catalog。

## 5. 身份和确认

聊天不要求项目，但仍要求登录和 owner 隔离。
读项目资料时必须先绑定授权项目并验证权限；普通聊天不能获得跨项目搜索权。
有副作用的动作必须经过可见确认；聊天中的“解释一下”不是执行许可，Skill 文本不是审批凭证。

## 6. 产品验收故事

1. 不创建项目直接三轮聊天，第三轮正确引用第一轮的合成内容。
2. 文本回复含普通段落，不因非 JSON 被判失败。
3. 一次工具调用后自然语言解释结果，轨迹和消息分开。
4. 加载一个通用 Skill 后按其格式回复，能解释当前加载了什么能力。
5. 模型失败→用户继续发消息→会话仍可用。
6. 运行中最小化/刷新→恢复同一消息而不重复执行。
7. 超长历史压缩不删除展示历史，不让模型绕过身份或审批。
