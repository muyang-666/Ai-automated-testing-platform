# 14. batch_apply_artifact_operations

用途：

> 一个用户意图包含多个相关的小修改，并希望只产生一个 Revision。


```text

```



# 18. Revision conflict

最关键场景：

```text

read revision=18

User/manual:
artifact → revision=19

```

Tool 必须返回：

```text

retryable=true
current_revision=19
```

然后：

> Agent 决定是否重新 read 后再次修改。

Tool Executor 不允许自动无限 retry。

# 29. Tool deterministic tests

每个 Tool 独立测试：

### Read

- owner；
- cross-user；
- missing artifact；
- limit；
- deleted node；
- stable ordering。

### Write

- valid operation；
- stale revision；
- forged user_id/project_id；
- invalid node；
- permission；
- cycle；
- cancel；
- batch rollback。

### Policy

- small add；
- single update；
- large delete approval_required；
- oversized batch rejected。

### Quality

- no mutation；
- deterministic output；
- empty Artifact；
- obvious duplicate；
- obvious boundary gap。

# 31. Eval case schema

例如：

```json
{
  "id": "minimal-edit-001",
  "artifact_fixture": "login_cases_v1",
  "conversation": [
    "把 TC003 的预期改成..."
  ],
  "expected": {
    "required_tools": [
      "read_artifact_nodes",
      "update_artifact_node"
    ],
    "forbidden_tools": [
      "delete_artifact_node"
    ],
    "changed_nodes": ["TC003"],
    "unchanged_nodes_except": ["TC003"]
  }
}
```

注意：

> Eval 不是要求模型每次完全一样调用 Tool。

# 32. Unintended Modification Rate

这是 P08 最重要指标之一。

例如：

```text
Artifact 有 50 个节点
用户只要求修改 TC003
```

正确：

```text
changed_nodes = {TC003}
```

如果 Agent 顺手改：

```text
TC004
group title
order
```

就是 unintended mutation。

必须可以自动计算。
