# V3 测试能力开发计划

> 前置：V2-P10 通过，或用户明确授权有边界的隔离试验。默认不在 V2 基础开发期间并行扩展业务。
> 本文件为新版本任务，旧编号只用于历史溯源，不重置已实现代码。

## 1. 版本与旧资产

| 新版本 | 目标 | 旧路线来源 |
|---|---|---|
| V3.1 | 用例生成 Skill：会话驱动、上下文、校验、审批、局部修正、效果评测 | 旧 V2.1 的 T05～T09 等 |
| V3.2 | 根因分析 Skill：冻结证据、确定性取证、结构化结论 | 旧 V2.2 |
| V3.3 | 测试数据准备 Skill：环境隔离、查询复用、审批写入 | 旧 V2.3 的造数任务 |
| V3.4 | 缺陷描述 Skill 与业务交互优化 | 旧 V2.3 的缺陷任务 |

通用权限、预算、上下文和恢复已属 V2；具体业务表、网络动作、测试质量门禁属 V3。

## 2. V3.1 用例生成

| 任务 | 交付 | 复用与验收 |
|---|---|---|
| V3.1-T01 | 旧成果审计与模型/数据就绪检查 | 验证现有 Workflow/工具/审批合同、孤立项目引用、场景绑定与真实返回；不重复建表 |
| V3.1-T02 | 对话 Agent 调用 case_generation 的桥接 | Skill 说明 + start/status/get_artifact 受控工具；任务返回 run_id，不阻塞整个对话 |
| V3.1-T03 | 人机协商、候选局部修正与审批 | 按来源/产物/版本绑定，修正生成新 revision；失效审批不得沿用 |
| V3.1-T04 | 真实业务闭环与 one-shot 对照评测 | 双来源、覆盖、重复、未知假设、保存幂等、成本和接受率，实际证据达标后才默认启用 |

保留旧生成入口和固定 Workflow；不在首轮重写为完全自由工具规划。通用 Agent 负责聊天/选能力，固定 Workflow 保证范围确认、覆盖计划、候选校验和保存审批。

## 3. V3.2 根因分析

| 任务 | 交付 | 关键边界 |
|---|---|---|
| V3.2-T01 | 运行证据快照与确定性解析 | 用执行时定义/代码/request/response，不拿当前代码冒充历史 |
| V3.2-T02 | 诊断 Skill、证据工具与验证 | confirmed/likely/inconclusive；绑定证据，不强行猜根因 |
| V3.2-T03 | 会话/Artifact UI、场景链路和质量评测 | 用户能追问依据；重跑/主动探测仍需独立审批 |

先设计证据合同再调用模型；不因具备通用 Agent Loop 就允许模型任意请求生产接口。

## 4. V3.3 测试数据准备

- V3.3-T01：环境/数据规则/只读查询工具，优先查找和复用合成测试数据。
- V3.3-T02：受限造数动作、审批、幂等、审计、清理和业务验收。
- 环境白名单、限量和数据生命周期强制执行；禁止接受任意 SQL、生产写入或复制实习敏感数据。

## 5. V3.4 缺陷描述

- V3.4-T01：输入事实与证据提取，生成结构化 defect_draft 和可复制描述。
- V3.4-T02：缺失信息追问、Artifact 编辑/版本及质量验收。
- 首期只产草稿，不自动提交外部缺陷系统；外部连接和发布权限另行授权。

## 6. 统一业务规则

- 每个 Skill 注册 required_context、允许工具、预算、输入/输出和版本。
- 业务动作每次重新检查用户/项目/环境权限，不能信任聊天上下文里模型给出的身份。
- 长任务由旧/新领域 Worker 按合同运行，返回任务引用；对话请求完成不是业务任务完成。
- 保存/造数/重跑与外部提交均需审批；自然语言意图不能替代后端操作授权。
- 普通问答不要求业务 Artifact Schema；业务产物不合法时应解释并在预算内修正，不能当自由聊天成功。
- 每项收尾只跑新增/受影响测试；对应版本验收时才组织综合回归。
- 不凭旧测试数字宣称 V3 完成，不凭模型选工具正确宣称最终业务结果正确。
