# 前端重构开发分档（草案）

> 状态：待确认优化细节。本文件只约定重构的推进顺序、范围与阶段交付物，不代表页面设计、接口改造或功能已开始。
>
> 定位：这是 `docs/` 下的独立前端重构规划，不归入 V1、V2 或 V3 的版本开发计划。

## 1. 重构目标与执行原则

本轮重构面向 TestMind 测试工作台的使用体验与前端可维护性。按用户完成测试工作的主路径推进：先建立 Agent 交互入口，再组织测试业务模块，随后收敛用例资产管理，最后完善支撑性管理能力。

各阶段均遵循以下原则：

- 不在未确认页面目标、使用者和关键操作前确定视觉方案或组件细节。
- 复用已确认的后端合同；接口字段、调用时机或写入语义需要变化时，单独列为接口改造项，不在前端重构中隐式变更。
- 每个阶段完成后先进行页面验收，再进入下一阶段；未确认的细节保留为待决项，不以占位交互当作完成。
- 保持已有功能可回归；重构期间的路由、权限、项目上下文和异常状态须有明确迁移方案。

## 2. 阶段总览

| 阶段 | 重构域 | 解决的核心问题 | 阶段结束产物 |
|---|---|---|---|
| 1 | Agent 交互页面 | 用户如何进入、理解并持续使用 Agent | 可验收的 Agent 工作台交互闭环 |
| 2 | 模块页面 | 用户如何浏览和切换测试业务模块 | 统一的模块入口、页面框架与导航关系 |
| 3 | 功能与接口用例管理页面 | 用户如何创建、组织、查看和维护用例资产 | 完整的功能/接口用例管理工作流页面 |
| 4 | 其它管理页面 | 用户如何完成配置、项目、权限和运行支撑操作 | 与主工作流一致的管理页面体系 |

## 3. 阶段一：Agent 交互页面

### 目标

建立以持续对话和测试任务协作为中心的 Agent 工作台，使用户清楚知道当前会话、Agent 状态、可执行操作和可见产出。

### 本阶段范围

- Agent 入口与会话主页面的整体布局。
- 对话消息、输入、执行状态、错误与恢复入口的呈现原则。
- Agent 过程信息与测试产出信息的分区关系。
- 与项目或测试上下文的关联方式。
- 桌面端与小屏场景下的基本可用性。

### 阶段交付物

- Agent 页面信息架构与关键用户路径说明。
- 经确认后的页面设计与可交互实现。
- 对应接口状态、加载/空白/失败状态的页面验收记录。

### 待确认的优化细节

- Agent 页面是独立工作台、主界面默认入口，还是以侧边面板形式出现。
- 对话、工具过程、测试产出（例如测试点或用例）的优先级与展示密度。
- 是否在本阶段纳入流式响应、历史会话、停止/重试、引用上下文等操作。

### 阶段完成条件

用户能从明确入口进入 Agent 页面，完成一次可理解的交互并看到相应状态与结果；不以静态聊天界面或仅能发送请求作为完成标准。

## 4. 阶段二：模块页面

### 目标

重组测试业务模块的导航与页面骨架，使用户能快速理解系统能力边界，并在模块之间保持一致的使用方式。

### 本阶段范围

- 模块首页、模块导航和模块切换关系。
- 模块层级、项目上下文和页面标题等公共信息的组织方式。
- 模块页面的共用布局、反馈状态与返回路径。
- 与 Agent 工作台之间的跳转或协作入口。

### 阶段交付物

- 模块地图与导航结构说明。
- 已确认模块页面的统一框架和首批重构实现。
- 关键模块切换、权限限制和无数据场景的验收记录。

### 待确认的优化细节

- 哪些现有页面应归并、拆分、隐藏或保留为独立模块。
- 模块导航采用侧边栏、工作台入口、快捷操作还是组合方式。
- 模块首页优先展示任务、资产、最近操作还是数据概览。

### 阶段完成条件

用户能够从模块入口理解各模块用途，连续完成跨模块跳转而不丢失必要上下文；页面结构不再依赖零散的独立入口。

## 5. 阶段三：功能与接口用例管理页面

### 目标

将功能用例与接口用例的管理体验整理为连贯的资产工作流，覆盖用户最常用的查找、维护与查看动作。

### 本阶段范围

- 功能用例与接口用例的列表、详情、创建和编辑页面关系。
- 需求、模块、场景、参数或接口文档等关联信息的呈现边界。
- 筛选、搜索、批量操作、状态反馈和空页面等管理操作体验。
- 从 Agent 产出进入人工查看、补充和维护用例的衔接。

### 阶段交付物

- 功能/接口用例资产的页面流程图与信息层级说明。
- 经确认后的管理页面重构实现。
- 创建、查询、编辑、关联查看及异常状态的验收记录。

### 待确认的优化细节

- 功能用例和接口用例是否共享列表/详情框架，哪些字段与操作必须区分。
- 用例编辑采用整页、分栏还是抽屉式交互。
- 本阶段是否纳入导入导出、批量生成、版本对比、评审或执行关联。

### 阶段完成条件

用户能在一致的页面结构内完成主要用例管理任务，并能看清用例与其关联测试资产的关系；不以单一列表改版作为完成标准。

## 6. 阶段四：其它管理页面

### 目标

收敛支撑主工作流的管理类页面，使项目、配置、运行和权限等操作在体验上与前三阶段一致。

### 本阶段范围

- 项目、需求、场景、参数文件、模型配置、用户权限、执行与报告等现有管理页面的重构排序。
- 表单、表格、详情、确认操作与风险提示等共用交互规范。
- 管理页面与主工作台之间的上下文传递与返回路径。
- 低频但高风险操作的可见性、确认与错误反馈。

### 阶段交付物

- 管理页面清单、优先级与归类说明。
- 统一管理页面框架及已确认页面的重构实现。
- 配置保存、权限控制、运行结果与错误处理等针对性验收记录。

### 待确认的优化细节

- 管理页的优先级，以及哪些页面仅做一致性调整、哪些需要流程重构。
- 模型配置、用户权限和执行操作的权限模型及风险确认方式。
- 是否将报告、执行记录和项目设置整合为项目级工作区。

### 阶段完成条件

管理类任务的入口、操作反馈、返回方式和风险提示与主工作流一致，且不会因重构削弱既有权限或数据操作保护。

## 7. 每阶段开始前的确认清单

在进入任一阶段实现前，确认以下内容，避免先做视觉或组件再回改业务流程：

1. 页面面向的主要用户与该页面的首要任务。
2. 必须保留、移除或新增的操作。
3. 页面涉及的后端接口、字段和权限边界是否维持不变。
4. 桌面端与小屏的支持范围。
5. 可用于验收的关键路径、空状态、失败状态和权限不足状态。

- 接口重构、数据库变更、后端权限规则或 Agent Runtime 的实现方案。
- 各阶段的工期、提交拆分和发布安排。
