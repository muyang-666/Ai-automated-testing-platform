# 09 — 验收清单

> 用于每次功能改造后的回归验收，确保已有功能不受影响。
> 第一阶段验收重点：项目管理 + 模块目录树 + 用例分类。
> 第二阶段验收重点：需求文本管理 + 功能测试用例管理 + 需求生成测试用例。

---

## 一、已有核心链路回归验收（每次必检）

### 1.1 用例 CRUD

- [x] 新增用例：填写名称、方法、URL、请求头、请求体、期望结果，提交后列表可见
- [x] 编辑用例：修改任意字段后保存，刷新列表确认修改生效
- [x] 删除用例：删除后列表不可见（软删除，`is_deleted = True`）
- [x] 查询用例：列表分页正常

### 1.2 AI 生成测试代码

- [ ] 选择一个用例，点击"AI 生成"，等待完成后确认生成代码非空
- [ ] 生成的代码可通过 Python 语法检查
- [ ] 生成的代码保存到了 `tests_generated/` 目录

### 1.3 规则生成测试代码

- [ ] 选择一个用例，点击"规则生成"，等待完成后确认生成代码非空
- [ ] 生成的代码可通过 Python 语法检查
- [ ] 与 AI 生成的结果不互相覆盖

### 1.4 pytest 执行

- [ ] 选择一个已生成代码的用例，点击"执行"
- [ ] 执行完成后可查看执行状态（通过/失败）
- [ ] 可查看执行日志
- [ ] 可查看响应状态码和响应体

### 1.5 AI 失败分析

- [ ] 对一个执行失败的用例，点击"AI 分析"
- [ ] 分析结果包含：问题现象、根因定位、责任归属、修复建议、风险等级
- [ ] 分析结果持久化保存，刷新后仍可查看

### 1.6 场景执行

- [ ] 创建场景，添加多个有序步骤
- [ ] 点击"执行场景"，确认按步骤顺序执行
- [ ] 步骤失败时确认后续步骤停止执行
- [ ] 场景执行结果汇总正确

### 1.7 报告生成

- [ ] 点击"生成项目报告"，确认报告生成成功
- [ ] 报告包含：测试范围概述、执行结果汇总、问题分析、风险评估、改进建议、结论
- [ ] 报告统计数据正确（总数/通过/失败/通过率）
- [ ] 报告列表可查看历史报告

### 1.8 参数管理

- [ ] 打开参数管理页，可查看当前 parameter.py 内容
- [ ] 修改变量值后保存，Python 语法校验生效
- [ ] 错误语法被拒绝保存

> **说明**：1.1 用例 CRUD 已通过前后端测试验证。1.2 ~ 1.8 为 AI/执行/分析/场景/报告链路，相关 6 个核心文件在第一/第二阶段均**零改动**，但需要人工执行回归测试确认。

## 使用说明

每次完成功能改造后：

1. 逐项勾选验证以上清单
2. **优先验证"已有核心链路回归验收"（第一部分）**，确保无回归
3. 再验证本次新增功能的对应验收项
4. 确认"暂不做"清单上的功能未出现
5. 发现问题记录到 `docs/07_CHANGELOG.md`
