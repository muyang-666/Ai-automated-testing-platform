# 09 — 验收清单

> 用于每次功能改造后的回归验收，确保已有功能不受影响。
> 第一阶段改造验收重点：项目管理 + 模块目录树 + 用例分类。

---

## 一、已有核心链路回归验收（每次必检）

### 1.1 用例 CRUD

- [ ] 新增用例：填写名称、方法、URL、请求头、请求体、期望结果，提交后列表可见
- [ ] 编辑用例：修改任意字段后保存，刷新列表确认修改生效
- [ ] 删除用例：删除后列表不可见
- [ ] 查询用例：列表分页正常

### 1.2 AI 生成测试代码

- [ ] 选择一个用例，点击"AI 生成"，等待完成后确认生成代码非空
- [ ] 生成的代码可通过 Python 语法检查
- [ ] 生成的代码保存到了 `tests_generated/` 目录

### 1.3 规则生成测试代码

- [ ] 选择一个用例，点击"规则生成"，等待完成后确认生成代码非空
- [ ] 生成的代码可通过 Python 语法检查
- [ ] 与 AI 生成的结果不互相覆盖

### 1.4 pytest 执行

- [ ] 选择一个已生成代码的用例，点击"执行"
- [ ] 执行完成后可查看执行状态（通过/失败）
- [ ] 可查看执行日志
- [ ] 可查看响应状态码和响应体

### 1.5 AI 失败分析

- [ ] 对一个执行失败的用例，点击"AI 分析"
- [ ] 分析结果包含：问题现象、根因定位、责任归属、修复建议、风险等级
- [ ] 分析结果持久化保存，刷新后仍可查看

### 1.6 场景执行

- [ ] 创建场景，添加多个有序步骤
- [ ] 点击"执行场景"，确认按步骤顺序执行
- [ ] 步骤失败时确认后续步骤停止执行
- [ ] 场景执行结果汇总正确

### 1.7 报告生成

- [ ] 点击"生成项目报告"，确认报告生成成功
- [ ] 报告包含：测试范围概述、执行结果汇总、问题分析、风险评估、改进建议、结论
- [ ] 报告统计数据正确（总数/通过/失败/通过率）
- [ ] 报告列表可查看历史报告

### 1.8 参数管理

- [ ] 打开参数管理页，可查看当前 parameter.py 内容
- [ ] 修改变量值后保存，Python 语法校验生效
- [ ] 错误语法被拒绝保存

---

## 二、第一阶段改造验收 — 项目管理

### 2.1 项目 CRUD

- [ ] 可创建新项目：填写名称和描述，提交后列表可见
- [ ] 可编辑项目信息（名称、描述），保存后刷新确认修改生效
- [ ] 可删除空项目（项目下无用例、无场景时）
- [ ] 项目列表正确显示（名称、描述、创建时间）
- [ ] 项目名称不可为空（后端校验）

### 2.2 默认测试项目

- [ ] 系统支持创建"默认测试项目"
- [ ] 数据库重建后，可手动创建默认测试项目
- [ ] 旧 Demo 数据（无 project_id 的用例）可正常显示和使用

### 2.3 项目筛选

- [ ] 前端支持切换到不同项目
- [ ] 用例管理页按当前项目筛选显示用例
- [ ] 切换项目后列表数据正确更新

---

## 三、第一阶段改造验收 — 模块目录树

### 3.1 模块 CRUD

- [ ] 项目下可创建一级模块（填写模块名称）
- [ ] 模块下可创建子模块（多级嵌套）
- [ ] 模块名称可编辑
- [ ] 模块名称不可为空（后端校验）
- [ ] 前端以树形结构展示模块目录

### 3.2 模块删除安全校验

- [ ] 空模块（无子模块、无用例）可正常删除
- [ ] 有子模块的模块删除时，后端拒绝并返回明确错误信息
- [ ] 有用例的模块删除时，后端拒绝并返回明确错误信息
- [ ] 前端根据后端返回的错误信息给出提示
- [ ] 级联删除不发生（删除模块不会自动删除子模块或用例）

### 3.3 模块排序

- [ ] 同级模块支持上移/下移调整排序
- [ ] 排序结果持久化，刷新后保持
- [ ] sort_order 正确更新

### 3.4 "未分类"默认模块

- [ ] 每个项目下可存在"未分类"默认模块
- [ ] "未分类"模块不可删除
- [ ] 未选择模块的用例显示在"未分类"下或标记为未分类

---

## 四、第一阶段改造验收 — 接口测试用例管理

### 4.1 新增字段

- [ ] 新增用例时 `project_id` 必填（不选项目无法提交）
- [ ] 新增用例时 `module_id` 可选（不选模块可提交，归属"未分类"）
- [ ] `case_type` 默认值为 `api`
- [ ] `source` 默认值为 `manual`
- [ ] `priority` 默认值为 `P2`
- [ ] `status` 默认值为 `draft`
- [ ] `is_deleted` 默认值为 `false`

### 4.2 用例按项目筛选

- [ ] 用例管理页可按项目筛选
- [ ] 选择项目 A 时只显示项目 A 的用例
- [ ] 切换项目后列表正确刷新
- [ ] 用例总数/分页正确

### 4.3 用例按模块筛选

- [ ] 用例管理页可按模块筛选/浏览
- [ ] 点击模块树节点，右侧用例列表筛选为该模块下的用例
- [ ] 点击"全部"或根节点显示当前项目所有用例

### 4.4 新建/编辑用例时选择项目和模块

- [ ] 新建用例表单中有项目选择器（下拉列表或当前项目上下文）
- [ ] 新建用例表单中有模块选择器（树形选择或下拉列表）
- [ ] 编辑用例时可修改项目归属
- [ ] 编辑用例时可修改模块归属
- [ ] 保存后归属正确持久化

### 4.5 旧数据兼容

- [ ] 旧 Demo 数据（无 project_id）不报错、不丢失
- [ ] 旧数据可正常显示在用例列表中
- [ ] 旧数据可正常执行、AI 分析

## 五、核心链路在改造后仍正常工作

在完成项目管理 + 模块目录树 + 用例分类改造后，逐条验证：

- [ ] AI 生成代码 — 选择带 project_id 的用例，生成成功后代码正确
- [ ] 规则生成代码 — 选择带 project_id 的用例，生成成功后代码正确
- [ ] pytest 执行 — 执行和日志采集正常，执行记录正确关联用例
- [ ] AI 分析 — 失败用例分析正常，分析结果正确保存
- [ ] 场景执行 — 场景内步骤正常执行，首失败停止策略有效
- [ ] 报告生成 — 项目报告生成正常，统计数据正确

## 使用说明

每次完成功能改造后：

1. 逐项勾选验证以上清单
2. **优先验证"已有核心链路回归验收"（第一部分）**，确保无回归
3. 再验证本次新增功能的对应验收项（第二至四部分）
4. 确认"暂不做"清单上的功能未出现（第七部分）
5. 发现问题记录到 `docs/07_CHANGELOG.md`
