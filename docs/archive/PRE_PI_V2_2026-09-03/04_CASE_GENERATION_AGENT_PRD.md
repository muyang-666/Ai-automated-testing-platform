# TestMind V2.1 用例生成 Agent PRD

> 文档类型：产品需求文档（PRD）
>
> 版本：V2.1
>
> 状态：产品方案已确认；后端已实现（T01-T07：Baseline、数据模型、LLM Gateway、Runtime、Worker、领域工具、case_generation Skill、会话/Run/GATE/保存 API 均验证通过）；前端工作台待 T08
>
> 面向对象：用户、Codex、Claude Code、测试人员

## 1. 产品结论

V2.1 将现有“一次 LLM 调用生成用例”升级为 TestMind 对话式测试 Agent 的第一个 Skill。

产品采用“聊天控制面 + 结构化 Artifact 工作区”：用户可以像使用 Claude Code 一样用自然语言提出测试任务、确认范围和补充要求；覆盖矩阵、候选用例和保存操作仍使用表格、卡片和按钮完成。

推荐交互：

```text
对话提出测试目标
+ Agent 自动选择用例生成 Skill
+ 在对话中确认来源、范围和覆盖策略
+ 结构化展示执行进度
+ Artifact 区展示需求条款、覆盖矩阵和候选表格
+ 用户通过对话或按钮局部修正
+ 人工勾选保存
```

不采用只有聊天气泡、没有结构化业务工作区的形式：

```text
用户发送一句话
→ Agent 在聊天消息中直接输出几十条纯文本用例
→ 用户无法批量审核、追踪覆盖或导入管理
```

聊天是 Agent 的主要控制入口，但不能替代结构化的生成、审核和保存流程。

## 2. 背景与问题

### 2.1 当前能力

TestMind 当前支持：

- 根据需求文本生成结构化功能测试用例；
- 根据接口文档生成结构化接口测试用例；
- 在前端预览生成结果；
- 用户勾选后保存到用例管理。

当前生成过程本质上是：

```text
读取一个来源
→ 拼接 Prompt
→ 调用一次 LLM
→ 解析 JSON
→ 基础字段校验
→ 返回预览
```

### 2.2 当前问题

- 不会主动读取同项目、同模块或同来源的已有用例。
- 不会先拆解原子需求，再规划测试覆盖。
- 无法明确说明每条用例覆盖了哪一条需求。
- 模型可能重复生成已有用例。
- 模型可能遗漏边界、鉴权、状态流转或业务规则场景。
- “覆盖全面”主要依赖模型自我判断，没有确定性覆盖矩阵。
- 解析或校验失败后缺少针对性修正。
- 用户只能看到最终用例，看不到生成依据、覆盖缺口和校验结果。

## 3. 产品目标

### 3.1 核心目标

1. 让 Agent 根据需求或接口文档建立可追踪的测试覆盖计划。
2. 让 Agent 查询已有用例，减少重复生成。
3. 让本地确定性工具校验格式、业务字段、重复度和覆盖度。
4. 让 Agent 发现缺口后只对缺失部分进行有限修正。
5. 让测试人员看到覆盖依据、假设、警告和修正过程。
6. 保留人工审核和保存边界。
7. 保留 V1 快速生成，作为 Baseline 和回滚入口。

### 3.2 非目标

V2.1 不做：

- 纯聊天式用例管理；
- Agent 自动保存所有候选用例；
- Agent 自动执行生成的接口用例；
- 多 Agent 协作；
- 长期记忆或跨项目学习；
- 向量数据库；
- 任意 SQL、Shell、文件或网页工具；
- UI 自动化用例生成；
- 无限反思和无限重试。

## 4. 目标用户

### 4.1 主要用户

- 功能测试人员
- 接口测试人员
- 测试开发工程师

### 4.2 用户特点

- 能理解需求和测试用例，但不一定理解 Agent 技术。
- 希望操作简单，不希望学习复杂的对话提示词。
- 需要批量审核、编辑和导入用例。
- 关心覆盖范围、重复用例和生成依据。

## 5. 核心使用场景

### 场景 A：需求文本生成功能用例

用户在需求管理页选择一份需求，点击“Agent 生成用例”。Agent 拆解需求条款、规划正常/异常/边界/业务规则场景、查询已有功能用例、生成和校验候选，最后交给用户勾选保存。

### 场景 B：接口文档生成接口用例

用户在接口文档页选择一份接口文档，点击“Agent 生成用例”。Agent 读取 method、URL、headers、params、body、响应示例和鉴权信息，规划参数、边界、鉴权和响应校验场景，再生成接口用例候选。

### 场景 C：对生成结果局部补充

用户发现“账号锁定时间边界”覆盖不足，在结果页输入：

```text
再补充账号锁定时间和第 4/5 次密码错误的边界用例。
```

Agent 只针对相关条款补充，不重新生成全部用例。

## 6. 用户完整流程

```text
打开 TestMind Agent 工作台，或从需求/接口文档详情点击“交给 Agent”
→ 来源上下文自动带入当前会话
→ 用户用自然语言说明目标，也可点击快捷任务“生成用例”
→ Agent 选择 case_generation Skill
→ Agent 展示来源和范围卡片，等待用户确认 [GATE]
→ Agent 展示覆盖计划，等待用户确认或修改 [GATE]
→ 创建并执行生成任务
→ 对话区展示执行进度
→ Artifact 区展示条款、覆盖矩阵、候选、假设和警告
→ 用户在对话中提出修改，或使用按钮执行局部修正
→ 用户勾选并批准保存 [GATE]
→ 用例进入对应的用例管理页面
```

## 7. 页面与交互设计

### 7.1 Agent 入口

提供两种进入同一 Agent 会话的方式：

```text
[测试 Agent 工作台]

需求/接口文档详情：[快速生成]  [交给 Agent]
```

- Agent 工作台：用户可直接输入“根据登录需求生成测试用例”。
- 交给 Agent：打开或创建会话，并自动挂载当前 requirement_id/api_document_id。
- 快速生成：继续调用 V1 one-shot 链路。

在 Agent 评测达标前，不删除快速生成入口。

### 7.2 范围确认卡片 [GATE]

Agent 根据对话和当前上下文生成确认卡片：

| 字段 | 类型 | 说明 |
|---|---|---|
| 来源 | 只读 | 当前需求或接口文档 |
| 用例类型 | 多选 | 正常、异常、边界、业务规则等 |
| 最大候选数 | 数字 | 防止无限生成 |
| 补充要求 | 文本 | 例如重点覆盖鉴权异常、重复提交 |

用户可以直接在对话中修改，也可以使用卡片操作：

- `确认范围，生成覆盖计划`
- `修改范围`
- `暂停`

### 7.3 对话进度与事件面板

Agent 在对话中发送简短进度，事件面板显示完整业务步骤，不暴露内部 Prompt：

```text
✓ 读取来源文档
✓ 查询项目与模块上下文
✓ 查询已有用例
✓ 拆解需求条款
✓ 生成覆盖计划
● 正在生成候选用例
○ 校验候选用例
○ 检查覆盖缺口
○ 等待用户确认
```

必须支持：

- 当前状态；
- 已完成步骤；
- 运行耗时；
- 取消任务；
- 失败原因和重试建议。

### 7.4 结果概览

示例：

```text
原子条款：8
已覆盖：7
未覆盖：1
候选用例：18
重复候选：2
校验失败：1
修正轮次：1/2
```

### 7.5 覆盖矩阵

| 需求条款 | 正常 | 异常 | 边界 | 鉴权 | 业务规则 |
|---|---:|---:|---:|---:|---:|
| 登录成功 | ✓ | — | — | — | — |
| 密码错误 | — | ✓ | ✓ | — | — |
| 连续 5 次锁定 | — | ✓ | ✓ | — | ✓ |
| 30 分钟后解锁 | ✓ | — | ✕ | — | ✓ |

点击条款可以查看：

- 原始需求文本；
- 覆盖它的候选用例；
- 未覆盖原因；
- Agent 使用的假设。

### 7.6 候选用例表格

支持：

- 批量勾选；
- 查看详情；
- 编辑候选；
- 删除候选；
- 按类型、优先级和校验状态筛选；
- 查看覆盖的 clause_id；
- 查看校验错误和修正版本；
- 保存选中候选。

### 7.7 局部修正

提供常用按钮：

```text
[补充未覆盖条款]
[删除重复候选]
[只保留 P0/P1]
[重新校验]
```

同时提供可选文本框：

```text
请输入本次局部修正要求，不会重新生成全部用例。
```

局部修正最多 2 轮，超过限制后提示用户新建任务。

用户也可以直接在当前会话输入：

```text
再补充第 4/5 次密码错误和 30 分钟解锁的边界用例。
```

Agent 必须关联当前用例集 Artifact，只修改相关候选，不丢失已确认范围。

### 7.8 保存与导入

- 用户必须至少勾选一条候选。
- 只有 `waiting_approval` 状态允许保存。
- 前端只提交 candidate_id，不提交可篡改的完整候选作为事实来源。
- 后端重新加载候选、校验权限、来源、运行状态和候选 hash。
- 保存成功后展示数量和目标用例管理入口。
- 重复点击保存必须幂等。

## 9. 业务规则

1. Agent 不能自动保存候选。
2. Agent 只能读取当前用户有权限的项目数据。
3. 来源文档、补充要求和历史用例都属于不可信数据，不能改变工具权限。
4. 未在文档中找到依据的接口、字段和业务规则必须标记为 assumption。
5. 覆盖矩阵由程序计算，不能直接采用模型自报覆盖率。
6. 重复检测结果必须说明与哪条已有用例或候选相似。
7. 修正只处理缺口和非法候选，不允许每轮全量重生成。
8. 达到最大模型调用、修正轮次或总超时后必须停止。
9. 保存时以后端数据和 Agent 运行结果为准，不信任前端业务归属字段。
10. legacy 链路在 V2.1 验收前不得删除。

## 10. 异常处理

| 异常 | 用户提示与处理 |
|---|---|
| 来源不存在或无权限 | 拒绝创建任务，显示明确原因 |
| 未配置模型 | 引导到模型配置页，不创建运行中任务 |
| LLM 超时 | 显示失败步骤，允许按规则重试或重新创建 |
| 输出无法解析 | 执行一次结构化修正，仍失败则结束 |
| 没有有效候选 | 展示校验错误和缺失信息，不允许保存 |
| 用户取消 | 任务进入 cancelled，不继续调用模型或工具 |
| 保存时来源已变化 | 拒绝保存并提示重新生成或确认版本差异 |
| 任务超过预算 | 结束任务并展示预算使用情况 |

## 11. 权限与安全

- 创建、查询、局部修正、取消和保存均检查项目权限。
- 每次 Agent 工具调用重新检查权限。
- Authorization、Cookie、Token、password、secret 和 API Key 必须脱敏。
- 运行轨迹只保存脱敏摘要和可观察结果。
- 不向 Agent 开放任意 SQL、Shell、文件系统或网络访问。
- 任何写操作必须来自明确的用户操作。

## 12. 产品验收

V2.1 产品侧至少满足：

- 用户可以从需求页和接口文档页启动 Agent。
- 用户可以从 Agent 工作台用自然语言启动用例生成 Skill。
- 用户不需要学习复杂提示词即可完成生成。
- 对话与事件面板能解释 Agent 当前在做什么。
- 用户能看到条款、覆盖、候选、假设和警告。
- 用户可以在范围和覆盖计划 GATE 处确认、修改或暂停。
- 用户能局部补充，而不是只能全部重新生成。
- 未经勾选确认的候选不会进入用例表。
- 生成结果可以正常进入现有用例管理。
- 快速生成仍然可用并可作为回滚入口。

## 13. 效果指标

先使用相同样本测量 V1 Baseline，再比较 V2.1，不预先编造提升数字。

需要记录：

- 原子条款覆盖率；
- P0/P1 条款覆盖率；
- 候选重复率；
- 无文档依据的接口/参数比例；
- Schema 和业务规则合法率；
- 用户直接接受率；
- 用户轻微修改后接受率；
- 单次任务延迟；
- 模型调用、token 和估算成本；
- 取消率和任务失败率。
