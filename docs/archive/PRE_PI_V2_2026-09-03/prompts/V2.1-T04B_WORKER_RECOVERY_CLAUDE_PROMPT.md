## 八、Worker 接口建议

命名可根据项目风格调整，但职责应类似：

```python
class AgentWorker:
    def __init__(
        self,
        session_factory,
        runtime,
        worker_id,
        now_provider,
        sleeper,
        poll_interval_seconds,
        stale_after_seconds,
    ): ...

    def run_once(self) -> WorkerRunResult: ...
    def run_loop(self, stop_requested=None, max_iterations=None) -> None: ...
    def recover_stale_runs(self) -> int: ...
```

要求：

- `run_once()` 没任务时正常返回 idle，不抛异常；
- 测试可以注入 session_factory、now_provider、sleeper；
- `run_loop()` 支持测试用 max_iterations，禁止测试无限循环；
- 生产循环可 sleep，但测试必须使用 fake sleeper；
- 捕获 KeyboardInterrupt 后正常退出；
- 不吞掉未知异常，必须让 Run 留下稳定状态和错误信息。

## 九、原子抢占

不要使用“先 SELECT queued，再直接把对象改成 running”的非原子流程。

推荐流程：

```text
1. 查询最早 queued run_id
2. 执行条件 UPDATE：
   WHERE id=:run_id AND status='queued'
   SET status='running', worker_id=:worker_id,
       heartbeat_at=:now, started_at=COALESCE(started_at,:now)
3. 检查 rowcount
4. rowcount=1：抢占成功并 commit
5. rowcount=0：被其他 Worker 抢占，有限重试下一个候选
```

要求：

- 抢占事务必须短；
- 抢占成功后提交，再进入 Runtime；
- 不能在 LLM/Workflow 执行期间持有抢占事务或行锁；
- worker_id 必须写入；
- 只能抢占 queued；
- cancelled、waiting_approval、终态都不能被抢占；
- 不依赖 MySQL 专属 `SKIP LOCKED`，首期保持 SQLite 测试兼容；
- 两个 Worker 看到同一 candidate 时，条件 UPDATE 只能允许一个成功。

## 十、Heartbeat

Heartbeat 表示 Worker 仍在处理 Run，不是每个消息的时间戳。

要求：

- 抢占时立即写 heartbeat_at；
- 每个 Workflow Step 开始前或完成后更新一次；
- heartbeat 更新必须校验 run_id、status=running、worker_id 一致；
- 其他 Worker 不能更新不属于自己的 Run；
- waiting_approval、succeeded、failed、cancelled 后不继续更新；
- 不新增后台 heartbeat 线程；首期通过步骤边界更新；
- 单个外部调用可能超过 stale_after 的风险登记为遗留，后续再评估独立 heartbeat。

如果 Runner 当前没有 hook，可增加最小可选 callback，例如 `on_step_boundary`，默认 None，保持 T04A 测试兼容。

## 十一、取消

- queued Run 被取消后不得抢占；
- running Run 在下一个步骤边界发现 cancelled 后停止；
- Worker 不得把 cancelled 改回 running/failed；
- waiting_approval 被取消后不得恢复；
- 本任务不实现 API，只验证 Service/Worker 行为。

## 十二、中断与 stale 恢复

stale 条件建议：

```text
status='running'
AND (
  heartbeat_at < now - stale_after
  OR heartbeat_at IS NULL 且 started_at < now - stale_after
)
```

恢复策略：

- stale running → interrupted；
- 记录稳定 error_code，例如 AGENT_WORKER_HEARTBEAT_TIMEOUT；
- 清理或保留 worker_id 必须在方案中统一；
- 不自动重排 queued；
- 不重新执行可能已经产生副作用的 Step；
- waiting_approval 不参与 stale 扫描；
- succeeded/failed/cancelled 不变化；
- 后续人工重试/重新排队留 T07 或独立任务。

## 十三、Runtime 集成

- Worker 通过 SkillRegistry 获取 Run 对应 Workflow；
- 未知 workflow_code/version 时，Run 进入 failed，不能永久 running；
- Runner 返回 waiting_approval 时 Worker 正常结束本次处理；
- Runner 返回终态时 Worker 释放资源；
- Runtime 异常必须先 rollback 当前失败事务，再用新事务记录 failed/interrupted；
- 每次 run_once 都关闭数据库 Session；
- 不把 Session ORM 对象跨数据库 Session 使用；
- 不调用真实 LLM Gateway，测试使用 Fake Workflow/Fake Gateway。
