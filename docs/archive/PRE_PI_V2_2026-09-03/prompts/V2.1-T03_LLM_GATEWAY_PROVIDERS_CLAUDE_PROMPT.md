## 八、统一数据合同要求

### LLMMessage

至少支持：

- role：system/user/assistant/tool
- content
- tool_call_id，可空
- name，可空

### LLMToolSpec

只定义模型可见工具 Schema，不执行工具：

- name
- description
- input_schema

### LLMToolCall

- id
- name
- arguments_json

### LLMRequest

- messages
- tools，可空
- temperature，可空
- max_tokens，可空
- timeout_seconds，可空
- response_mode：text/json/pydantic
- metadata，不得包含 Secret

Pydantic 类型对象无法直接序列化时，可以由 Gateway 方法参数单独接收 `response_model: type[BaseModel] | None`，不要硬塞进 JSON Schema。

### LLMResult

- content
- parsed，可空
- tool_calls
- provider_name
- model_name
- prompt_tokens，可空
- completion_tokens，可空
- duration_ms
- request_id，可空
- finish_reason，可空
- raw_metadata：只保留非敏感、必要字段

## 九、Provider Adapter 合同

定义统一 Protocol/ABC，例如：

```python
class LLMProviderAdapter(Protocol):
    provider_type: str

    def complete(
        self,
        provider,
        model,
        request,
        response_model=None,
    ) -> LLMResult:
        ...
```

要求：

- Adapter 只负责请求/响应转换，不查询数据库；
- Gateway 负责按 provider_type 选择 Adapter；
- Gateway/现有配置 Service 负责场景与模型解析；
- Adapter 不保存 AgentRun/AgentStep；
- Adapter 不执行 tool_calls；
- 错误转换为统一异常类型；
- 不在异常中泄露 API Key、Authorization 或完整敏感 payload。

## 十、结构化输出策略

两级策略：

1. Provider/Model 原生支持结构化输出时，使用原生能力。
2. 不支持或兼容性未知时，要求 JSON 文本，再用 Pydantic 校验。

校验失败：

- 抛出 `LLMOutputValidationError`，包含安全的字段级错误摘要；
- 本任务不自动再次调用模型修正；修正循环由未来 Skill/Runtime 控制。

不要在 Gateway 内实现无限重试或 Prompt 修复循环。

## 十一、统一异常

至少区分：

- LLMConfigurationError
- LLMTimeoutError
- LLMProviderError
- LLMRateLimitError
- LLMOutputValidationError
- LLMUnsupportedFeatureError

异常要求：

- 具有 error_code；
- 用户可读 message；
- 可选 retryable；
- 不包含 Secret；
- 保留原始异常链 `raise ... from e`，但 API 输出不得暴露内部对象。

## 十二、Retry 规则

- timeout、连接错误、HTTP 429、HTTP 5xx：最多有限重试；
- 400/401/403、模型不存在、输出 Schema 错误：不重试；
- 重试次数和间隔必须可测试；
- 测试中禁止真实 sleep，可注入 sleeper 或把重试关闭；
- 写清 Adapter SDK 自带重试与 Gateway 重试如何避免叠加。

不要引入 Tenacity，除非源码核验后证明手写重试明显不合理，并先申请依赖授权。
